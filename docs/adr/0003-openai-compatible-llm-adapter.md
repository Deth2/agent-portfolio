# Adapter generico "OpenAI-compatible" invece dell'SDK nativo del provider

Vogliamo poter cambiare provider LLM (Groq in produzione, Ollama in locale, eventualmente OpenRouter/Together) senza riscrivere il codice applicativo. Groq, Ollama, OpenRouter e Together espongono tutti un endpoint `/v1/chat/completions` compatibile con il formato OpenAI: invece di integrare l'SDK nativo di Groq, abbiamo isolato tutta la configurazione (base URL, API key, nome modello) in `lib/llm/client.ts`, letta da variabili d'ambiente (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`). Il resto dell'app dipende solo da `lib/llm/chat.ts` (`askAboutCv(...)`), non dal provider. Costo accettato: se in futuro serve un provider non compatibile OpenAI (es. Anthropic nativo), va scritto un adapter diverso dentro lo stesso file — ma i call site restano invariati. Limite noto: questo rende banale lo swap _di configurazione_, non rende Ollama deployabile su Vercel (vedi [ADR-0001](0001-groq-free-tier-for-chat-agent.md)) — resta utile soprattutto per sviluppare in locale contro Ollama e deployare in produzione contro Groq.
