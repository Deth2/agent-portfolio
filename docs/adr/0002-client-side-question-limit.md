# Question Limit lato client invece di rate limiting lato server

La chat è pubblica e senza autenticazione, quindi serve un modo per contenere l'uso (e i costi/quota del tier gratuito Groq). L'alternativa più robusta sarebbe un rate limiting lato server per IP (es. Upstash Redis), ma introduce un servizio esterno aggiuntivo da configurare e mantenere. Per la prima versione abbiamo scelto un **Question Limit lato client** (contatore in sessione, soglia di 5 domande, poi messaggio che invita a usare i Contact), attivabile/disattivabile via variabile d'ambiente, di default attivo. È facilmente aggirabile (basta una sessione nuova/incognito) — è una misura di UX e contenimento costi "soft", non una vera misura di sicurezza. Se in futuro emergesse abuso reale, va aggiunto un rate limiting server-side per IP come misura complementare, non sostitutiva.
